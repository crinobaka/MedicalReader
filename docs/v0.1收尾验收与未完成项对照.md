## 本次 Commit 12 补齐

### 1. 主导航响应式化

手机继续使用底部 NavigationBar；宽屏切换为 NavigationRail。

这解决了“把桌面导航硬塞进手机”的问题，也避免在 ReaderPage 内到处加入平台判断。

### 2. 用户 DIY 教程

新增《用户与 DIY 指南》，覆盖：

- 第一次使用
- 手机 / Windows 操作
- 书签
- 阅读器主题
- UI DIY
- 书籍模板
- 两个文字冒险式生成器
- 目录文本格式
- 裁剪规则
- 常见故障处理

### 3. 收尾边界

v0.1 仍然有一些适合独立大版本处理的事项：

- 高级裁剪的完整自动吸附、区域语义判断和多方案可视化编辑器。
- 真正的 GPU shader 玻璃珠式放大镜；当前版本已经具备缩放/平移输入基础，但没有引入新的高风险渲染依赖。
- 完整的 Annotation / Knowledge Graph / MRIF 大规模数据层。
- 云同步、EPUB、MOBI、AI、手写等 PRD 明确冻结的功能。

这些不是 Commit 12 的“漏交”，而是为了避免在 v0.1 收尾时引入新的大型依赖和高风险重构而明确冻结的范围。

## 与原工程路线的关系

原路线要求 v0.1 首先打通：

```text
导入医学书
    ↓
建立书库
    ↓
定位页面
    ↓
阅读
    ↓
标注
    ↓
保存知识
```

当前代码已经具备 PDF 导入、Library、阅读、搜索、书签、笔记、附件、书籍目录/页码映射以及模板系统的基础闭环。

## 发布前人工检查

在真实设备上只需要重点检查：

- Android：外部存储授权、重启后 Library、PDF 打开。
- Android：竖屏、横屏、滑动翻页、双指缩放。
- Windows：PDF 打开、滚轮翻页、Ctrl+滚轮缩放、键盘跳页。
- Windows：Rust `medical_core.dll` 与构建产物一起发布。
- Reader：书签添加 → 退出 → 重进 → 仍存在。
- Note：Markdown、HTML、图片、音频附件路径。
- Template：复制内置模板 → 修改 → 保存 → Reader 加载。
- Directory generator：使用本文档的 2 空格格式生成一次 `book.json`。

## 收尾原则

> 默认配置必须直接好用；DIY 是给愿意折腾的人，而不是普通用户的入场考试。
>
> 能用 Flutter 原生能力解决的问题，不再为了“看起来高级”增加一个高风险依赖。
